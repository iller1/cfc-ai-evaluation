# CFC + HAWM Founding Beta v2 — Recruitment Runbook

## Target

Recruit 3–5 genuinely engaged companies for the first wave.

Use `FOUNDING_BETA_RECRUITMENT_PACK.md` as the compact company-facing/outreach package.

Do not optimize for sign-ups. Optimize for participants willing to run real bounded workflows and give usable feedback.

## Best target profile

A strong first participant:

- already uses LLMs in research, review, evaluation or decision support;
- has a recurring point where an AI conclusion must be checked before action;
- can provide sanitized/structured inputs;
- has a human reviewer;
- can run several cases within a short beta period;
- understands experimental beta limitations.

## Avoid first-wave targets

Avoid companies whose only useful workflow requires:

- sensitive personal data;
- regulated high-risk decisioning;
- autonomous action;
- deep production integration before value can be tested;
- procurement/security review disproportionate to a £10 experimental beta.

## Outreach sequence

### Step 1 — initial message

Goal: determine whether they have a matching workflow.

Do not lead with a long technical explanation.

Suggested structure:

1. narrow problem;
2. what Founding Beta measures;
3. one bounded workflow;
4. human remains final;
5. ask whether they have a use case worth testing.

### Step 2 — workflow screen

Use FOUNDING_BETA_COMPANY_INTAKE.md.

Outcome must be one of:

- ACCEPTED;
- ACCEPTED WITH CONDITIONS;
- NOT YET ACCEPTED;
- DECLINED.

### Step 3 — onboarding

For accepted participants:

- agree workflow boundary;
- agree data boundary;
- name human reviewer;
- explain NO CUSTOMER CONTENT BY DEFAULT;
- provide START HERE + limitations;
- test first case together;
- confirm feedback route.

### Step 4 — minimum engagement

Working proposal for first wave:

- at least 5 real cases during the agreed beta period;
- at least one structured feedback summary;
- immediate reporting of false allow / false stop / unexpected persistence / access issue.

Exact minimum remains an owner/commercial decision until finalized.

## Signal handling

One report = finding.

Same problem across independent companies = product signal.

Do not prioritize a feature merely because one participant requests it unless it improves measurement quality, safety or real-workflow usability.

## Success for wave 1

Success is not "5 companies signed up".

Success means:

- companies actually use the system;
- we obtain reproducible cases;
- we see where CFC/HAWM stops too much, allows too much or communicates poorly;
- repeated needs become visible;
- fixes are versioned and regression-tested;
- at least some participants want to continue into the next round.
